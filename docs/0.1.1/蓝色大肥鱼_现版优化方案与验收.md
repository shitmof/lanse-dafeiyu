**关键澄清（避免 DeepSeek 误解）：**

- “玩游戏气急败坏”“原地专心玩魔方”“下五子棋”“吃Token”等只是已存在的本地动画名字；播放它们不安装游戏、不启动游戏、不读取游戏，也不消耗模型 token。保留全部玩耍/时节素材，并让它们真正参与闲置轮播。
- “挑一个动作”不得 `startActivity`；只有“回到小窝”“和我聊聊”这类明确入口才前置 App。图5、图6 已经说明原版是在宠物菜单里直接换，只是手机端要把三列大菜单改为同一面板逐级替换。
- **完整分类为 13 类 106 段**：待机 1、转向 1、拖拽 1、点击回应 5、移动 3、小动作 18、玩耍 27、吃什么 12、时节 21、文字 2、余额档位 6、碎碎念 3、工作状态 6。当前 Android `catalog.json` 的 10 类是旧界面合并后的结果；0.1.1 必须恢复 13 类，并同步修改 `scripts/prepare_assets.py` 的分类映射后重新生成目录，不能只改界面标签。
- 点击框不能隐形变大：宠物窗、气泡窗、菜单窗都是局部小窗；人物周围原透明空白应让下层应用可点，不能用全屏透明层截获所有触摸，也不能只缩背景、保留旧热区。
- 吃饭/睡觉时段只调权重，不整小时绑同一段；固定位置只禁止位移，不禁止换动作；移动动画与真实位移必须由同一次计划驱动。
- 本地动作/时节/玩耍/定时/默认台词都不调用模型；零 token 指没有发送生成请求，不表示余额查询不联网，也不承诺所有服务永久免费。

## 1. 这次要做成什么样

这是一只在手机当前屏幕直接互动的小宠物。用户不离开正在使用的应用，就能拖动到左右边缘、换动作、按原版分类点播、切换本地工作姿态及调整自动播放。主 App 保留设置、动作浏览、聊天记录和存档功能。

| 优先级 | 用户要求 | 完成的可见结果 |
| --- | --- | --- |
| P0 | 图1、图2左右拖不动 | 以人物可见边界限制位置，靠近屏幕边缘，不再被大片透明画布挡住 |
| P0 | 图3长按框太大 | 紧凑浮窗菜单，实际窗口与点击区域一起缩小，其他应用仍可操作 |
| P0 | 点“挑一个动作”跳 App | 直接切换当前悬浮宠物；分类选择也在小浮窗完成 |
| P1 | 106段实际只看见少数 | 全分类可手动点播，日常自动播放扩大覆盖、避免连续重复 |
| P1 | 手机没有电脑任务也想用工作动画 | 本地选择思考、工作、整理、等待、成功、出错；显示为陪伴姿态，无模型调用 |
| P1 | 自己定时换动作 | 可选播完自动换、自定义间隔或暂停，保存选择，熄屏不后台补播 |
| P1 | 余额真实且不花模型token | 使用余额专用接口，展示真实金额、时间和错误；不发送聊天请求 |
| 配套 | 中文名称、公开源码、注明来源、可回退 | 显示名称统一“蓝色大肥鱼”，保留原版署名与素材限制，保留0.1.0源码和APK |

图4反映当前 App 动作列表是大卡片、平铺浏览；它可以保留为档案入口，不能代替浮窗点播。图5、图6只展示了原版分类的一部分，实施依据必须是原始配置与源码中的完整目录，而非只抄截图中能看见的条目。

**“玩游戏气急败坏”“下五子棋”“原地专心玩魔方”“吃Token”等都是动画名字。** 播放已有本地动画不需要安装游戏、不读取游戏、不调用模型，也不会因为叫“吃Token”就真的消耗 token。这版不加入第三方游戏安装或游戏引擎。时节动画也允许日常点播，不因现实日期不匹配就从目录删掉。

## 3. 边界、坐标与触摸方案

### 3.1 可见人物能靠边

1. 在资源准备阶段为全部106段生成稳定的动画级元数据：原始尺寸、全帧可见并集`visualBounds`、角色主体范围`bodyBounds`、脚底/主体锚点、是否允许镜像。透明阈值应保留柔和边缘；alpha≥16用于本次诊断，不可直接当作无损裁剪标准。自动提取后复核尾巴、头饰、道具、文字和特效宽动作。
2. 优先采用紧凑的实际宠物窗口，按元数据平移绘制原帧，保持人物大小及比例，不把裁剪后的图片重新拉伸至旧画布宽。切换动作保持脚底/主体锚点，不随每帧包围盒抖动。
3. 边界、保存坐标、拖动、甩动、回弹、漫游统一以主体锚点和可用显示区域计算。人物可见外缘与左右可用边界目标间隔为0–8dp；不默认让人物完全出屏或做边缘隐藏功能。
4. 特效/文字超出主体时，优先利用朝向及合适的屏内播放位置处理。只有独立图层才能单独重排或缩小附属效果；现有合成WebP不能假定可拆分。人物贴边与完整宽特效冲突时，提供具体动作截图评审取舍，不能擅自重绘、删减，也不能又用整张透明画布限制所有普通动作。
5. 朝向翻转时，包围盒同步做`[W-right, W-left]`变换；文字类禁止镜像。禁止只改`lp.x`为负数后假定所有Android厂商都会允许透明区越界。
6. 使用一致的WindowMetrics/WindowInsets坐标模型，API28提供兼容分支。处理状态栏、刘海、手势/三键导航、旋转及多窗口变化；不得重复扣除Insets。系统限制区域按实际权限行为处理。

### 3.2 点击框不能隐形变大

宠物窗、气泡窗、菜单窗都是局部小窗，不能用全屏透明层截获所有触摸。`touchBounds`不能沿用480×270大画布；点击人物周围原透明空白处，应能操作下层应用。不能认为View返回`false`就一定跨Window透传，必须在另一应用上实测。必要时把不可交互特效单独作为不可触摸窗口，并遵守系统对悬浮遮挡触摸的限制。

动作窗口尺寸变化不应抢焦点、改变当前前台Activity或中断下层输入。三只宠物时逐只验证位置和热区，停止后所有窗口清除。

## 4. 紧凑的浮窗交互

原版的关键是“动作→分类→具体动作”直接点播。移动端保留这套完整层级，在**同一块小面板内逐级替换**，不同时铺开电脑端的三列大菜单。

建议主菜单5项：**换个动作、动作分类、工作状态、自动播放、更多**。

| 入口 | 具体行为 |
| --- | --- |
| 换个动作 | 立即从合适本地池选不同动作，在当前宠物播放一次，结束后恢复原模式 |
| 动作分类 | 显示13个原版分类；点分类在同一面板列出动作，局部滚动；返回上一级不打开App |
| 工作状态 | 六档本地姿态及“恢复自动”；支持一次演示或持续该状态 |
| 自动播放 | 播完自动换 / 自定义间隔 / 暂停自动切换；开启或关闭漫游独立控制 |
| 更多 | 保留和我聊聊、吃一碗白饭、说句话、查余额、安静/碎碎念、回到小窝、停止陪伴；局部滚动 |

“回到小窝”明确前置App。现有“和我聊聊”可保留进入聊天页的行为，属于显式打开聊天；本次不扩建QQ式聊天。选动作、换动作、状态切换、自动模式设置不得调用`startActivity`。App动作页仍能浏览、搜索、点播，但调用相同的目录及调度器。

**建议默认尺寸（候选值，以用户手机截图验收为准）**：宽144–168dp且不超过可用宽度44%；文字12–14sp；内边距6–8dp；圆角8–12dp；可见高度不超过`min(288dp, 可用高度34%)`。普通行高40–44dp，面板不再用8个高行全部展开。长名称换行或省略后可查看全名，不裁掉无法辨认。

菜单靠近宠物并自动选择上方/下方、左侧/右侧，保持在可用屏幕内；外点可收起。默认根菜单面积目标 **≤整屏12–15%**（目标12%），同手机、同显示缩放下 **≤图3旧菜单面积60%**。不得仅缩字体、保留巨大背景或透明点击框。系统大字体/无障碍模式应允许至少48dp触摸目标并局部滚动，单独验收，不用把字强压小来满足面积指标。停止陪伴最多从主菜单点两次，通知栏仍可直接停止。

分类面板必须来自原版 **13类完整目录**（不是旧界面的10类合并标签）；点分类后在同一面板列出该类的全部动作，局部滚动，返回只回上一级，不打开App。

## 5. 动画调度与去重

### 5.1 一个调度器负责一次播放

把“动画播放”和“决定播什么”分开。建议职责为`AnimationCatalog`（完整目录与元数据）、每宠物`PlaybackController`（状态/队列/去重）、`PetView`（解码与一次播放）、浮窗菜单（发意图）、位置控制（移动/边界）。名称可按工程风格调整，职责必须清晰。

默认用动画结束回调驱动下一段，而不是全片无限循环再每30秒强行覆盖。注册/注销回调、解码代次校验、停止/熄屏/重建后的旧回调失效必须一起处理；加载失败可记录并切换下一候选，不能高速重试卡死。预解码下一段或使用受控双缓冲，避免白闪，限制缓存内存，不能一次解码106段。

优先级：停止/熄屏 → 拖拽等直接触摸 → 手动点播/状态 → 已启用的远程事件 → 普通自动播放。手动一次播放完恢复原模式；用户再次手动选择可立即覆盖。漫游动作与位移来自同一次计划，不能由另一个计时器不断改为奔跑。每只宠物各有播放代次、队列和历史，避免控制一只却让三只同步换片。

### 5.2 自动池、历史与覆盖

- 常规自动候选共85段：待机1、转向1、移动3、五个日常分类80。默认保持小动作/玩耍/吃什么/时节/文字等原版权重方向，增加公平覆盖机制。当前 `catalog.json` 把原版13类合并成10类（小动作并入日常、吃什么并入吃饭等），实现时必须先恢复13类目录，再让自动池从“小动作/玩耍/吃什么/时节/文字”五类取80段；否则界面分类与调度会继续错位。
- 推荐“按类别加权、类别内洗牌袋、全局最近6段排除”；选择仍有未播项的类别，85段完整覆盖后再重建本轮池，避免固定待机项在每次抽取中压缩丰富度。权重可调整顺序，但不能让某类永远饿死。
- 其余21段：拖拽1、点击5、余额6、碎碎念3、工作6按事件触发或手动点播，不伪装成真实事件。全106段始终可手动选择；另提供本地“全动作巡演”检查模式，按清单逐段播放并记录结果，余额/工作类标明动作演示。
- 点按回应从原版完整5段轮换，不再硬编码4项。候选≥2不连续重复；候选不足时缩短历史排除窗口，单候选持续状态可重复，但这是明确例外，不是去重失败后死循环。
- 饭点、睡眠提高相关类别权重或选一组动作，不能把整小时绑在同一段。固定位置只关闭位移，不关闭动画变化；关闭漫游时移动动画可原地展示或明确从自动池排除，验收按启用池计算，手动入口仍保留。
- 文字类`noMirror`必须由数据驱动；切换移动朝向后也不能把文字翻反。

### 5.3 定时和工作姿态

“播完自动换”为默认。自定义间隔建议5–300秒可调，定义为**最短切换间隔，且播完当前段再换**：片长超过间隔时不截断；片长较短可停留末帧等到间隔，或用户显式选择期间循环。暂停自动切换时继续当前片或暂停画面应有清楚文案，不偷偷恢复30秒计时器。

本地工作状态六档为思考、工作、整理、等待、成功、出错；可选一次展示/持续状态，退出恢复自动。持续单段可重复，气泡标为“本地陪伴状态”，不用“正在替你执行任务”误导。仅用户显式启用DSH同步时再订阅真实任务事件；本地/远程冲突按当前模式处理，状态来源可辨认。

设置落盘：自动模式、间隔、漫游、固定位置、静音及本地状态是否持续。重启恢复应可预期；熄屏暂停播放和自动切换，亮屏只恢复一次，不补发熄屏期间积压动作。停止/权限撤销后清理回调、解码引用、网络任务与窗口。

## 6. 余额与零模型token边界

| 操作 | 允许的执行方式 | 是否需要模型token |
| --- | --- | --- |
| 拖动、点按、全部动画、玩耍、时节、定时、手动工作状态 | 本地素材与状态机 | 不需要 |
| 默认说句话、默认碎碎念 | 本地固定文案，明确离线 | 不需要 |
| 查DeepSeek余额 | 用户主动触发`GET https://api.deepseek.com/user/balance` | 不调用生成模型 |
| 用户主动AI聊天、显式启用AI碎碎念 | 沿用已配置的对话服务 | 会按服务计费；本次不扩展 |

官方余额接口返回`balance_infos`（币种、总额、赠送额、充值额）及可用标识，见[DeepSeek官方接口文档](https://api-docs.deepseek.com/api/get-user-balance/)。显示实际币种与金额，多个币种分别展示，不混加；不得让模型猜余额，401/超时不能展示伪造的零元或成功。

请求中显示“查询中”；成功记录更新时间；失败时若保留旧数据，显著标注“缓存/上次查询时间”。并发请求合并，建议手动刷新30秒内节流并解释；自动查询默认关闭。配置密钥不能顺带开启AI碎碎念或后台余额轮询。不支持余额的其他API服务明确提示“不支持”，不悄悄请求对话接口。

余额动画是装饰，不是金额来源。若要映射六档，使用可解释的固定规则或用户明确设置的基准；官方接口没有给出总充值预算/使用百分比，不能伪造“已用百分比”。手动点播六档时只说明动作演示。

零token指没有发送模型生成请求，不代表余额查询不联网，也不承诺所有服务永久免费。现有实际API账户尚未连接验收，交付时必须保留该状态直到有真实证据。
