# v0.1.2：游戏模式与自然行为实施计划（独立于 0.1.1-test.2）

状态：**计划，不随 test.2 实现。** 前置条件：`0.1.1-test.2` 的左右边界修复在用户真机通过。若前置失败，先修边界，不启动本阶段。

## 1. 目标

在保留现有 106 段动画、拖动、点击、长按菜单、六档本地工作状态、AI/DSH/余额能力的前提下，增加：

1. 用户手动切换的**游戏模式**：缩小、靠边、暂停漫游、降低气泡、可隐藏/恢复。
2. 轻量**本地行为控制器**：NORMAL / INTERACTING / IDLE / WORKING / RESTING / GAME_MODE，带优先级、冷却和防抖。
3. 为未来语音/QQ 预留事件与连接接口，但本阶段不接 QQ、不监听麦克风。

不引入 Kotlin、游戏引擎、无障碍权限、Root 或全局触摸拦截。

## 2. 游戏模式

### 2.1 入口

- 长按菜单增加“游戏模式”开关（或“更多 → 游戏模式”），复用现有紧凑面板，不新增常驻按钮。
- 通知栏增加“游戏模式”动作；恢复入口始终存在。
- 首次切换显示一次说明：缩小/靠边/减少气泡；不读取其他应用内容。

### 2.2 行为

- 尺寸：临时使用较小的 `size`（建议 180–220dp，具体以窄屏实测为准），退出恢复用户原尺寸；不修改用户设置。
- 位置：停靠到当前屏幕侧边；保留 `Edge` 语义，动作切换仍吸附。
- 漫游：`wander` 的动作位移暂停；随机动画继续（可低频）。
- 气泡：暂停主动碎碎念/AI 自动气泡；点击/手动查询仍可显示。
- 隐藏：窗口设为不可见（不是停止前台服务），通知提供“显示桌宠”；**不承诺触摸穿透**。
- 恢复：点击通知动作或 App 内按钮；恢复时重新测量屏幕、恢复尺寸和边缘。
- 退出游戏模式恢复用户原 `size`、气泡设置、漫游设置；不覆盖六档工作状态。

### 2.3 触摸穿透限制

- 可探索 `FLAG_NOT_TOUCHABLE` 的纯展示态；一旦需要点击/长按/拖动，必须恢复可触摸。
- 不使用无障碍、Root、`SYSTEM_ALGORITHM_WINDOW_TYPE` 或全局 hook。
- 全屏拖动载窗（test.2 引入）仅限手指按下期间；游戏模式不常驻全屏窗口。

## 3. 行为控制器

### 3.1 状态

| 状态 | 进入 | 退出 | 行为 |
| --- | --- | --- | --- |
| NORMAL | 默认 | 交互/工作/休息/游戏 | 85 段洗牌袋、自动间隔 |
| INTERACTING | 点击/拖动/菜单/语音输入 | 手势结束 + 2s 冷却 | 用户动作优先，不自动打断 |
| IDLE | 无交互 5–10min | 交互/工作 | 低频小动作、降低气泡 |
| WORKING | 六档工作状态/DSH 工作 | 清除工作/DSH 结束 | 持续本地工作动画，不伪造任务进度 |
| RESTING | 用户手动/夜间安静/熄屏 | 亮屏/交互 | 待机/睡眠动作，暂停漫游 |
| GAME_MODE | 用户手动 | 用户手动 | 见第 2 节 |

### 3.2 优先级与防抖

- 用户输入（INTERACTING）> WORKING/GAME_MODE > IDLE/RESTING > NORMAL 自动动作。
- 自动调度在 `dragging`、`menuOpen`、工作持续、游戏模式、熄屏时暂停。
- 每次状态切换至少 2s 冷却；重复状态不触发动画重启。
- 不改变现有 85 段池/洗牌袋/最近 6 段排除/5–300s 间隔。
- 状态机只在本地运行；无模型连接也能工作；不增加自动 AI 调用。

### 3.3 事件接口（逐步拆分，不一次性重写）

建议新增轻量 Java 接口/类，保留现有 `PetService` 行为：

- `PetEvent`：CLICK / LONG_PRESS / DRAG_START / DRAG_END / MENU_ACTION / WORK / SLEEP / WAKE / GAME_MODE / VOICE（预留）。
- `BehaviorController`：接收事件，决定状态/动画/是否允许气泡；纯本地。
- `PetRenderer`：窗口、裁切、位置、边缘、气泡（可从 PetService 逐步抽出）。
- `AiConnection`：现有 `PetApi` 的接口边界。
- `MessageBridge`：未来官方许可的 QQ 机器人接口；不读取密码/私人聊天，不申请无障碍。

首版可以让 `PetService` 继续持有渲染，只新增 `BehaviorController` 与枚举，避免大爆炸式重构。

## 4. 设置与持久化

新增 `Prefs` 键（建议）：

- `game_mode`（boolean，默认 false）
- `game_mode_size`（int，默认 200）
- `game_mode_hidden`（boolean，临时）
- `behavior_idle_minutes`（int，默认 8）
- `behavior_cooldown_ms`（int，默认 2000）
- `behavior_notice_shown`（boolean）

不新增密钥/令牌字段；不改变现有包名、SharedPreferences 文件和数据迁移规则。

- 先出 debug 测试包；不覆盖 `v0.1.0`、`v0.1.1-test.1`、`v0.1.1-test.2`。

- 游戏模式不改用户原设置；崩溃/异常退出时恢复原尺寸与可触摸状态（使用持久化恢复标记，不依赖进程存活）。

## 6. 验收

### 6.1 游戏模式

- 菜单/通知可反复开关 20 次；尺寸、边缘、漫游、气泡、隐藏/恢复均正确。
- 隐藏后只留通知入口；恢复后位置/尺寸/动画正常。
- 游戏模式退出恢复原 `size`/wander/whisper，不改变工作状态。
- 不读取屏幕内容，不申请无障碍，不增加常驻全屏窗口。

### 6.2 行为

- NORMAL/INTERACTING/IDLE/WORKING/RESTING/GAME_MODE 六状态可观察（debug 日志）。
- 用户拖动/点击/菜单期间自动动作不打断；冷却/防抖生效；无闪烁。
- 85 段池、106 段手动、六档工作状态、余额、离线台词、DSH 原能力不回归。
- 无网络/无模型时全部本地行为可用；自动行为不产生模型请求。

### 6.3 测试分层

- 自动化单元测试：状态优先级/冷却/边缘/调度可抽成纯 Java 类；至少覆盖状态转移和防抖。
- 模拟器交互测试：菜单/通知开关、拖动、点击、长按、熄屏/亮屏、1–3 只、旋转、三键/手势。
- 真机测试：用户手机；不得用模拟器替代。

## 7. 包体积与性能（独立分析，不阻塞本阶段）

现状约 250 MiB，主要来自 106 段 480×270 透明 WebP。先做无风险分析：

1. 统计 `animations/`、`memes/`、DEX、资源、对齐/压缩占比；记录每段帧数、时长、文件大小、解码内存。
2. 检查重复/近似资源、未引用表情、WebP 质量/帧率/尺寸参数；用 `ffprobe`/Pillow 对比。
3. 评估按需下载/分资源包、AVIF/WebP 参数、解码缓存上限；**保留全部 106 段、27 表情、透明通道、时长和可接受画质**。
4. 只有收益明确且画质/解码对比通过才改包；否则保留现状。

输出体积、画质、内存、CPU 对比和回退方案，不把未验证的压缩包作为正式版。
